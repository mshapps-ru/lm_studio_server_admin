Задавай при необходимости вопросы и отображай ответы в плане

Давайте cделаем загрузку списка моделей полученных из lm studio server из эндпоинта /v1/models. Список полученных моделей давай сохранять в файле config.json и в аналогичном формате как получаем из /v1/models. В файле давай хранить в формате:
"LmStudioModelList": [
{
"id": "gpt-oss-20b",
"object": "model",
"owned_by": "organization_owner"
}
]

Список моделей давай обновлять раз в 5 минут автоматически по расписанию в бэкенде. Если список моделей изменился, только тогда список моделей обновляем в файле config.json. При ошибках получения списка моделей из эндпоинта /v1/models ничего не делаем, просто пишем в лог что не удалось получить список моделей.

Также давай в config.json добавим хранения дефолтных параметров для запуска моделей командой lms load "имя модели" "параметры для запуска". Сохранение параметров предусмотри в формате key - value чтобы в дальнейшем список параметров можно было менять без доработок кода.

"LmStudioModelDefaultLoadParameter": [
{
"contextWindow": 100000,
"ttl": 600
}
]

Ниже пример запуска модели gpt-oss-20b с параметрами "contextWindow": 100000 и ttl 10 минут

lms load gpt-oss-20b --context-length 100000 --ttl 600

Необходимо в файле config.json индивидуальные параметры запуска моделей моделей и использовать их для запуска если указаны:

"LmStudioModelLoadParameterList": [
{
"model": "gpt-oss-20b",
"contextWindow": 120000,
"ttl": 1200
}
]

Учти что некоторые индивидуальные параметры могут пересекаться с параметрами по умолчанию. При старте нужно использовать в приоритете параметры указанные в параметре "LmStudioModelLoadParameterList".
Сохранение параметров предусмотри в формате key - value чтобы в дальнейшем список параметров можно было менять без доработок кода.
